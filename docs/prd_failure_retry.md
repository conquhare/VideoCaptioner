# PRD：字幕处理失败的重试机制 + 前端失败提示 + 结果区手动重试按钮

- 项目：VideoCaptioner（本地视频字幕生成工具，Python + PySide6 / QFluentWidgets 桌面应用）
- 文档版本：v0.1（简单 PRD）
- 产品经理：许清楚（Xu）

## 1. 背景与现状

- 自动重试已存在：LLM 网络层使用 tenacity 指数退避（429 / 空响应，最多 10 次）；断句 agent loop `MAX_STEPS=2`；优化有反馈循环。
- 子任务失败目前被「优雅降级」吞掉：
  - `split_by_llm.py:36-38` 断句失败 `return [text]`，退回原文；
  - `optimize.py:148-149` 批处理失败只 `logger.error` 并跳过该批；
  - `optimize.py:183-184` 单条失败跳过。
  - 结果：UI 静默，用户不知道有失败。
- 主流程级失败（整段崩溃、LLM 欠费 403、模型 503）会 `raise` → 线程 `self.error.emit(str(e))` → UI `subtitle_interface.py:518 on_subtitle_optimization_error` 用 `InfoBar.error()` 弹顶部通知条。这条链路已通。
- UI 通知组件：qfluentwidgets 的 `InfoBar`（顶部通知条）、`MessageBoxBase`。
- 处理线程：`subtitle_thread.py`（单字幕优化 / 翻译）、`subtitle_pipeline_thread.py`（全流程）、`transcript_thread.py`（转写）。字幕数据结构 `ASRData`，每条字幕有 `index`（key）。

## 2. 产品目标

1. 让所有处理失败对用户可见：致命失败立即弹窗提示，子任务降级失败在结果区明确标注。
2. 让失败可低成本恢复：提供与失败粒度匹配的手动重试入口，且重试具备幂等性（只重发失败项，不重跑成功项）。
3. 保留并增强自动重试：自动重试覆盖瞬时/网络类错误，手动重试覆盖自动重试仍失败或用户主动决定的场景。

## 3. 两种场景定义

- 单任务（Single）：针对单条字幕或单段文本的一次操作。
  - 例：优化一条字幕、翻译一条字幕、对一段文本整体重新断句。
- 批量任务（Batch）：针对整个字幕文件的一次操作。
  - 例：整个字幕文件的优化、翻译、断句；整条处理流水线。

## 4. 失败分类与弹窗策略

- 致命失败（Fatal）：整段任务中断，无法继续。
  - 例：LLM 欠费（403）、模型服务 503、网络中断、线程崩溃。
  - 提示策略：复用 `InfoBar.error()` 顶部通知条，文案包含原因与建议动作（如「余额不足，请充值后重试」），并提供「重试」「取消」按钮（进入 `MessageBoxBase` 或 InfoBar 的交互）。
- 子任务降级失败（Degraded / Silent）：主流程继续，但部分结果不可用。
  - 例：某批优化失败、某条翻译失败、断句失败退回原文。
  - 提示策略：不在顶部打断用户；在结果区对应字幕条目上标记「失败」状态，并就地提供「重试」按钮；当批量任务结束时，用一条汇总 `InfoBar.warning()` 告知「N 项失败，可在结果区重试」。

## 5. 手动重试粒度决策表

| 操作 | 单任务场景 | 批量任务场景 | 重试粒度建议 | 理由 |
|------|------------|--------------|--------------|------|
| 断句（split） | 对一段文本重新断句 | 对整个字幕文件重新断句 | **重试该段 / 重试全部失败段**（按 chunk 为单位，不按单条字幕） | 断句以一段整体文本为操作单元，单条字幕无独立断句语义，重试必须整段重来 |
| 优化（optimize） | 重试该单条字幕 | **重试失败项 / 重试全部失败项**（逐条或逐批） | 优先「全部失败项」批量按钮；允许单条精修 | 优化按条 / 按批进行，可精确重试；失败多时逐条点累，需批量入口；幂等：只重发失败项 |
| 翻译（translate） | 重试该单条字幕 | **重试失败项 / 重试全部失败项**（逐条或逐批） | 优先「全部失败项」批量按钮；允许单条精修 | 同优化，逐条 / 逐批可精确定位；幂等：只重发失败项，省 token / 额度 |

粒度使用说明：

- 重试一项：单条优化 / 翻译失败，或用户想精修某一条时使用。
- 重试该批：断句失败时，对该段文本整体重试；优化 / 翻译的某一批失败且失败项连续时，可对该批重试。
- 重试全部失败项：批量任务结束时汇总提示处 / 结果区工具条提供；一键重发所有失败项，跳过已成功项。

## 6. 自动重试 vs 手动重试的分工

- 自动重试（保留并增强）：
  - 覆盖瞬时错误：网络抖动、429 限流、空响应、超时。
  - 策略：tenacity 指数退避，上限 10 次；断句 loop `MAX_STEPS` 适度上调（建议 2→3，待确认）。
  - 对用户透明，失败仍存在时进入手动重试入口。
- 手动重试（新增）：
  - 覆盖自动重试仍失败的场景，以及用户主动决定重试（如网络恢复后）。
  - 幂等：只重发失败项，不重跑已成功项。
  - 与失败可视化绑定：失败处即重试入口。

## 7. 用户故事

P0：

- 作为用户，当批量优化部分条目失败时，我希望在结果区看到哪些条失败并一键「重试全部失败项」，以便快速恢复而不重跑成功项。
- 作为用户，当发生致命失败（如欠费 403）时，我希望看到明确弹窗提示原因与后续动作，以便知道下一步该做什么。

P1：

- 作为用户，当断句失败退回原文时，我希望结果区标注「断句失败」并提供「重新断句」按钮，以便按段重试。
- 作为用户，当单条翻译 / 优化失败时，我希望在该条附近直接「重试」，以便精修该条。

P2：

- 作为用户，我希望失败汇总 InfoBar 显示失败数量并可点击定位到第一个失败项。
- 作为用户，我希望重试过程显示进度（如「重试中 3/10」）。

## 8. UI 交互描述（文字）

- 失败标记：结果区每条字幕增加失败状态（如红色角标或「失败」文字标签）。
- 单条重试按钮：失败字幕条目右侧出现小「重试」按钮（图标 + 文案）。
- 全部失败项重试：结果区工具条 / 汇总 InfoBar 中提供「重试全部失败项（N）」按钮。
- 致命失败弹窗：使用 `InfoBar.error()` 顶部通知条；如需更强交互，使用 `MessageBoxBase` 弹出「原因 + 重试 / 取消」。
- 断句失败：该段对应的字幕分组处显示「断句失败」标记，提供「重新断句」按钮。

## 9. 待确认问题

1. 自动重试参数是否增强？断句 `MAX_STEPS` 是否从 2 上调到 3？tenacity 上限是否维持 10 次？
2. 「全部失败项」批量重试时，是否需要并发控制（避免再次触发 429）？建议并发=1 或小并发 + 退避。
3. 重试期间是否锁定编辑、避免数据竞争？失败项状态如何在 `ASRData` 中表达（新增 status 字段？）。
4. 断句失败的重试是整段重来，是否会覆盖用户已手动编辑的结果？需要确认覆盖策略。
5. 403 欠费等致命错误是否需要区分「不可自动重试」（需用户先处理余额）并禁用手动重试直到条件满足？
6. 翻译 / 优化重试的幂等实现：是否需要在 `ASRData` 中记录每条的「成功 / 失败」状态，以支持只重发失败项。
